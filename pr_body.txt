🎯 **What:** The testing gap addressed
The `VelopackUpdateService` handles application updates via Velopack, but tests covering its internal exception paths (such as `HttpRequestException`, `IOException`, and `UnauthorizedAccessException`) during `DownloadUpdatesAsync`, `CheckForUpdatesAsync`, and `ApplyUpdatesAndRestart` were missing. Because the underlying `UpdateManager` is a sealed dependency and directly instantiated, testing these exception handlers was previously very difficult.

📊 **Coverage:** What scenarios are now tested
- Abstracted the hard dependency on `Velopack.UpdateManager` by creating an `IUpdateManagerWrapper` interface and a `Func<IUpdateManagerWrapper>` factory.
- Injected this via an internal constructor in `VelopackUpdateService` to allow precise mocking of the dependency in tests while preserving the existing public API.
- Added tests for `DownloadUpdateAsync` when it throws an exception to ensure the status correctly transitions to `UpdateStatus.Error`.
- Added tests for `CheckForUpdatesAsync` failing, ensuring it returns `false` and sets the status to `UpdateStatus.Idle`.
- Added tests for `ApplyAndRestart` failing, ensuring the status is set to `UpdateStatus.Error`.

✨ **Result:** The improvement in test coverage
The `VelopackUpdateService` class now has robust, deterministic unit tests for its internal exception and failure paths, preventing regressions and guaranteeing that UI-bound states respond appropriately when external network or file operations fail.
